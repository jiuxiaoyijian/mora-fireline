# UI 风格与交互层级

研究与实施日期：2026-09-17。**木框纸面 UI 已接入正式游戏（0.2.0-dev.4）。下文保留设计依据；实施状态见本节。**

已实现：委托/标题/结算公告板、常驻任务签、建造与演练底栏切换、菜单收纳设置与重置、镜头/图层展开、复盘地图高亮；取消 1920×1080 整体缩放，适配桌面、横屏和竖屏。正式版按钮至少 48 CSS px，宽屏复盘为侧栏，窄竖屏用可滚动面板。

仍待验证或实现：真人体验、真实手机安全区/触控、双指镜头手势；当前触屏通过镜头按钮操作。正文核心信息 16px，辅助说明 12–14px；未声称所有文字达到 16px。样稿仅保留为视觉对照，不随 Pages 主入口发布。

推荐「浅木框 + 暖纸张 + 鼠尾草绿行动按钮」：委托和结算采用公告板，常驻 HUD 用轻薄纸签，工具区用低矮木托盘。先减少重复信息，再更换材质；不把整屏深蓝简单改成整屏棕色。

样稿：[ui-study.html](prototypes/ui-study.html)。本地 `npm run dev` 后打开 `/docs/prototypes/ui-study.html`；可切换风格、桌面/手游横屏、标题/建造/演练/结算等状态。复用当前 3D 场景，数值为示例，未接入建造与规则，不写存档。普通文件双击或 Pages 地址不能直接运行其 TypeScript 模块。

## 1. 检索结论与选型

低多边形描述模型造型，不规定唯一 UI 风格。以下适配判断基于本项目的林缘小镇、规划员身份和自然色调，不是行业定律。

| 方向 | 合适之处 | 问题 / 使用位置 |
| --- | --- | --- |
| 木制公告板 + 纸张（推荐） | 材料呼应木石住宅，委托像镇上的便笺；能表达准备、签收、报告 | 厚木框仅用于低频大面板；常驻 UI 减薄，木纹不铺在正文背后 |
| 浅纸张 + 扁平自然色 | 干净、轻量，适合资源、工具说明、手机小屏 | 单独使用容易普通，结合少量木框、图章建立识别 |
| 星露谷式像素木框 | 手工感和乡村题材贴近，可借鉴公告板/日志的用途 | 现有场景并非像素渲染，直接混入像素字体、重描边会冲突；不复制游戏素材 |
| 深蓝指挥台 | 状态对比强 | 用户已明确反馈不佳；冷色大块过重，与当前温暖微缩场景不协调 |

已查看《星露谷》任务页面的公告板截图及日志入口：木板承载纸面任务，任务细节按需展开；不是把完整任务正文一直压在地图上 [S1]。Kenney 的 RPG UI 组件提供简化边框/纸面参考，页面标注 CC0，但本轮没有导入资源 [S2]。

### 视觉规范（提案）

| 元素 | 建议 |
| --- | --- |
| 阅读底色 / 文字 | 暖纸 `#FFF3D9` / 深棕 `#453A2C`；正文区域不加高频木纹 |
| 木框 / 边缘 | 浅木 `#B88952` / 木褐 `#93663B`；适量倒角和轻阴影，不用厚重黑投影 |
| 主行动 | 鼠尾草绿 `#506746` + 浅字 `#FFF6E0`；同一界面一个最突出的行动 |
| 选中 / 警告 | 选中用浅绿底、实线框与标记；火险/破坏才用陶土红，同时提供图标或文字 |
| 字体 | 易读中文无衬线正文；标题可略带书卷感。保留当前字库，避免小号像素字体 |
| 动效 | 点击下压、面板短淡入；减少动态效果偏好下取消装饰动画。先验证，不增加大面积模糊 |

## 2. 改版前问题与调整

| 当前情况（代码核对） | 调整 |
| --- | --- |
| 顶部目标、左侧委托、提示卡重复解释任务；阶段也有两处展示 | 合为一个可展开任务签；常驻只留目标和阶段，背景故事进入委托详情 |
| 全屏/声音/帮助/菜单并列，辅助图层四项及镜头五键同时常驻 | 顶部保留一个菜单；地图辅助与镜头各一入口，常用操作在一级展开面板 |
| 建造期显示等待时间、速度；演练时工具栏大面积禁用 | 按状态替换底栏：建造工具 ↔ 播放控制，隐藏当前无用途的信息 |
| 默认街区/清空与撤销相邻 | 撤销留在工具区；重置/清空移到菜单，危险操作与高频建造分开 |
| 结算与复盘都重复成果、下一步，地图被整层报告遮住 | 结算给结果和改进方向；复盘给定位线索，地图与事件列表并排 |
| 整体按 1920×1080 等比缩放 | 3D 场景随窗口适配，HUD 按可用宽高重排，保持真实触控大小 |

改版前 `src/ui/stage.ts` 的缩放规则在 844×390 下为 0.361；53px 菜单按钮约显示为 19px，16px 辅助文字约为 5.8px。这个计算反映当前缩放实现，尚非真机测量。

## 3. 手游通用规则怎样落到本项目

平台与通用 UX 规范提供触控、安全区、反馈依据；具体角落布局和以下数值目标属于本项目设计选择。

| 依据 | 项目规则 |
| --- | --- |
| Android 建议触控目标至少 48dp，并提供手势替代入口 [S3] | Web 样稿按钮实际布局高度至少 48 CSS px；原生 dp 与 CSS px 不混为同一单位，最终真机验收。镜头手势同时配按钮 |
| WCAG 2.2 的目标最小尺寸为 24×24 CSS px，存在间距等例外 [S4] | 24px 不是本项目手游按钮目标；高频触控采用 48px，主按钮 52–56px，间距建议 ≥8px |
| 系统栏、挖孔及横屏边缘可能遮挡控件 [S5] | 交互区避开安全区；Web 使用 `env(safe-area-inset-*)`，再留 12–16px 内边距；背景可延伸 |
| 渐进披露：低频/高级选项放二级入口 [S6] | 目标、预算、当前工具常驻；格线/镜头/声音按需打开，不把开始和暂停藏进菜单 |
| 状态可见、可撤销、识别优于记忆 [S7] | 点击即时反馈；选中工具和费用持续可见；可撤销操作不逐次确认，破坏布局或放弃火情才确认 |
| 正文对比度 4.5:1，大字 3:1 [S8] | 文字落在稳定纸面，按最终叠加色验收；火险/成功同时用文字，避免仅靠红绿 |
| 《星露谷》移动版有单独控制方式与设置 [S9] | 借鉴按设备设计输入的思路，不直接把桌面整体缩小，也不照搬移动摇杆 |

建议横屏以「上方看状态、下方做操作、中央看地图」组织；单关建造不是带大厅/商城/背包的运营游戏，不需要套用五栏底部导航。双手横屏左右触达需真机验证，不宣称某一个角落适合所有玩家。

## 4. 各界面的信息与交互层级

L0：场景；L1：常驻 HUD；L2：按需展开面板；L3：阻断式结果/确认。正常路径最多一层展开面板；结果到复盘采用替换，避免弹窗叠弹窗。

| 界面 | 优先信息与呈现 | 主操作 | 次级操作 / 返回 |
| --- | --- | --- | --- |
| 标题 / 首次委托 | 低对比场景背景 + 木框纸面：身份一句、8/12 目标、12 点预算 | 接受委托，开始规划；有存档时为继续规划 | 玩法、设置；重新规划为低频项并确认 |
| 建造 | 左上任务签，右上资源与菜单；底部工具 + 费用，选中后单行说明 | 右下开始演练 | 撤销留工具旁；地图辅助/镜头按需展开；住宅不足时原位说明原因并引导补齐 |
| 预警 | 短提示：山火方向、3→1 倒计时；清楚标为演练 | 暂停/继续 | 建造输入锁定；不再重复身份长文 |
| 演练 | 尚未起火住宅数、目标与时间；底栏替换为播放控制 | 暂停，原位切换继续 | 1×/2× 与查看结果；图层可开，隐藏预算与建造工具；不把“尚未起火”提前称为“已保住” |
| 暂停 | 小纸卡说明状态已保留 | 继续演练 | 返回建造需要确认放弃进度，设置；恢复时沿用原速度 |
| 结算 | 大数字保住户数 → 达标/差距 → 一句改进提示；预算与上次差值为次级 | 保留布局，继续改进 | 查看起火线索；12 户全保时主文案可改为完善方案，不虚构下一关 |
| 复盘 | 目标地图 + 事件摘要列表，默认首起火；点选事件高亮位置/来源 | 去调整布局 | 返回结果/展开完整事件；不将当步来源写成完整原因 |
| 系统菜单 | 继续、设置、帮助；重置/清空单独危险区 | 返回游戏 | 返回标题保留布局；在运行中打开自动暂停，关闭不暗中恢复 |
| 设置 | 声音、标准/流畅画质、全屏状态，说明当前值 | 关闭返回 | 应用后立即反馈，真机不支持项明确说明；不写技术调试数据 |
| 帮助 / 委托详情 | 三步流程、关键规则；操作按鼠标/触屏/键盘呈现 | 明白了，返回原处 | 不靠 hover 显示必读文字；键盘地图保留入口 |
| 地图辅助 / 镜头 | 每组最多一层列表；开关有清晰状态，镜头有复位 | 选择后看场景 | 再点入口、关闭键或返回收起；不强制暂停建造 |
| 确认 | 动作名称 + 会丢失什么/保留什么 | 明确动作，如恢复默认布局 | 取消为安全返回；不用模糊“确定” |
| 提示 / 错误 | 地块附近短反馈，预算不足或住宅不足在相关控件旁保留 | 继续当前任务 | 不抢焦点；重要错误不能只闪一条 toast |

## 5. 适配和输入

- **桌面/平板**：顶部分散状态、底部工具，中央建筑区尽量无遮挡；参考效果以本项目交互样稿为准。
- **手游横屏**：预算、目标保留；已安置数在不足时突出，完整时可收入任务签。工具+撤销一排，播放阶段仅留播放条。目标为常驻面板占屏 ≤25%（项目目标，非通用规范），以 844×390、740×360 实测。
- **竖屏**：采用独立布局或明确建议旋转；不能继续把全套横屏压缩。可选上半地图、下半可收起建造面板；历史样稿未完成竖屏适配；正式版已采用上下布局，仍须真机检验。
- **触控**：点选工具后点格建造；防火带拖绘。双指镜头手势进入时取消尚未确认的单指建造，不应误下单。搬迁显示选中与取消，任何关键功能提供按钮替代。双指镜头规则待实现；当前提供镜头按钮，并忽略第二触点的建造输入。
- **弹层**：打开时焦点进入，Tab 不漏到底层，Esc/系统返回先关顶层，关闭回原入口；遮罩阻止底层建造。正式实现复用并调整 GameDialogs，避免新增独立暂停逻辑。

## 6. 实施顺序与验收目标

1. 先拆出 HUD 状态布局，合并目标/阶段，移走低频入口；保持规则、存档、键盘网格不变。
2. 替换深蓝主题，统一木框/纸面/按钮状态；中文正文先保障大小和对比度。
3. 场景与 UI 缩放解耦，再做安全区、触控冲突、横竖屏策略。
4. 复盘增加地图定位。真人测试能否说清目标、找到工具/暂停/撤销、依据线索重试。

验收：每个状态只有一个明显主行动；目标与工具说明不重复；844×390 实际按钮高度 ≥48px、正文目标 ≥16px；地图建造不被展开层穿透；长文可滚动且操作可达；31 项规则/性能回归保持通过，另做 UI 流程和真机测试。样稿是设计验证，不表示这些生产验收已经完成。

### 本轮样稿核对

AI 浏览器已检查桌面与 844×390 横屏预览、风格切换、建造→预警→演练→暂停/恢复→结算→复盘→建造，以及菜单、帮助、重置取消、地图格线和镜头。横屏建造按钮实际 DOM 尺寸最小为 48×48 CSS px；控制台无 warning/error。手机预览是桌面浏览器中的定尺寸画框，不等于真机或完整响应式验收；弹层仍以浏览器窗口居中，设置/撤销/事件定位仅为示意。
