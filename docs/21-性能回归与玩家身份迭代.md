# 性能回归与玩家身份迭代

日期：2026-09-17。状态：已实现、自动检查及 AI 浏览器 QA；尚无真人试玩结论。

## 定位与修复

建造原来每次重建 64 格，现在只替换变化的地块，并释放旧几何体。退出演练仍重建全部地块以恢复烧毁前的状态。远景按材质合批；静态阴影缓存，仅布局和烧毁状态改变时更新；住宅状态按模拟步更新；传播路径仅在开启时生成并合为一条线段对象；拾取只检查地面和建筑主体。标准画质 DPR 上限 1.5，流畅模式上限 1 并关闭阴影；逻辑规则不变。

## 浏览器性能证据

同一内置浏览器，1280×720、DPR 1、默认布局、标准画质，各主要阶段 600 帧。前后数据见 evidence/performance-before.json 与 performance-after.json。性能采样显式通过 ?perf=1 开启，不上传数据。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 规划绘制调用 / 帧 | 810 | 345 |
| 规划 CPU P95 | 8.8ms | 5.5ms |
| 演练绘制调用 / 帧 | 859 | 397 |
| 演练 CPU P95 | 8.9ms | 6.5ms |
| 规划平均 FPS | 32 | 32 |
| 规划帧间隔 P95 | 31.7ms | 31.6ms |

CPU 指 RAF 回调的执行时间，不是 GPU 时间。帧率没有明显提升，不能将调用下降写成卡顿完全解决，也尚不能确定约 32 FPS 的原因。需在用户实际设备、独立浏览器继续定位帧调度与 GPU 成本。

最终界面版本五次建造 B2/B3/B5/B6/B7，单次布局更新为 1.6/1.0/0.8/0.9/0.7ms，见 performance-after-edits.json。旧版 layoutMaxMs 30.8ms 包含初始化及重置，不能与上述单次更新直接比较。

## 回归方法

运行 npm run check：26 项规则检查、4 项性能结构检查、CPU 基准、类型检查及生产构建。npm run test:perf 可单独执行性能回归。

结构门槛：连续五次编辑保留未修改对象并释放被替换几何体；退出模拟恢复全部地块；远景不超过 24 批且保留实际几何；统计正确保留长帧。CPU 基准预热 9 次后循环测量 60 次完整 450 步模拟，同时断言 0/6/12 户结果。默认 P95 上限 100ms，可用 PERF_SIM_BUDGET_MS 调整；这是跨机器的严重退化门槛，不是 60 FPS 承诺。本轮 P95 5.54ms、最大 6.64ms。

浏览器回归需单独执行，不能用 Node 测试代替：生产预览加 ?perf=1，固定 1280×720、DPR 1、标准画质，恢复默认布局；采集标题、规划、默认演练各 600 帧，保存可见 JSON；随后五次建造、撤销、重试、路径开关、切流畅画质。比较 CPU P95、帧间隔 P95、慢帧数、绘制调用、几何体数量及编辑耗时。相同设备同条件 CPU P95 超基线 25% 或规划调用超 400 时应调查；帧率低于目标仍需独立设备实测。不要混合不同画质和布局的样本。

## 身份与目标方案

玩家是松风镇防灾规划员。居民已撤离，委托是让 12 户人家有家可归：8 户为最低承诺，12 户为完整守护。标题建立身份，常驻委托卡保持目标可见，演练结算解释完成程度与下步方向。重复尝试被解释为防线演练；尚未增加多关、居民角色或长期成长系统。

界面采用深蓝规划席、金色行动按钮和选中工具，与暖色低多边形山谷分开；减少模糊效果。菜单提供流畅画质。该方案已可体验，但身份代入、目标记忆和界面辨识度需要真实首次玩家验证。

建议真人验收：进入后询问“你是谁、要保护什么、怎样算完成”；观察能否主动完成一次规划—演练—调整；记录首次注意到目标的时间及是否混淆演练与真实灾害。不要提前解释以替代界面的引导。
