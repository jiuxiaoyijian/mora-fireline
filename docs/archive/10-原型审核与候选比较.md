# 使用 game-prototype-triage 审核 v0.1 与重新选型

日期：2026-09-15。审查基线：`0a0d79f`，游戏实现提交 `82d59e9`。

方法来源：用户提供的 `game-prototype-triage-SKILL.md`《游戏原型命题：选型与降本方法论》。用户明确要求使用该 skill 审核当前方案并考虑更合适的新原型。本轮只做评审、定向测量和文档更新，不更换游戏方向、不修改运行时规则、不公开部署。

## 结论先行

当前方向符合题面，也符合 skill 推荐的「将物理灾害降级为确定性状态传播」路线。问题主要在具体原型的决策结构，而不是选择了建造灾害这个方向。

**在当前项目继续交付的条件下，优先推荐《火线街区：三次防灾实验》：将自由沙盘收敛为短回合、可比较、配表驱动的实验挑战。若决定完全重选，优先验证《双视点巡检》异常观察原型。** 新候选尚未实现，不能声称已经证明更好玩或更省时。

过去已经投入多少时间不作为保留原型的理由；现有输入、渲染、存档、测试与部署基础能减少后续成本，这部分应计入选择。

## 1. 校正评分口径

skill 提供了有效的选型框架，但其中的强断言需要区分为「题目要求」「经验规则」「未验证推测」。

| skill 中的判断 | 本次采用方式 |
| --- | --- |
| 聚焦玩法、体验循环、AI 协作和迭代 | 题目明示，作为优先级依据 |
| 过程记录可能占一半 | 题目没有权重，不作为事实或计算依据 |
| 3D 不可被 2D 替代，否则没答题 | 原题要求 3D，但未要求玩法必须无法二维化；作为差异化指标，不设成淘汰条件 |
| 美术和功能投入都是负收益 | 过量投入应避免；辨识度、可读反馈与基本完成度仍影响体验 |
| 原创有加分、砍功能比做完得分高 | 可解释的取舍有助评审，具体得分并无题面依据 |
| 单次循环 ≤ 60 秒 | 采用为内部设计目标；不是招聘方规定，也不能把 45 秒模拟误算成完整循环 |
| 内容可系统生成 | 采用「配置表 + 受约束装配」，不为满足此项新增随机地形、自动求解器等高成本系统 |
| 单 HTML + CDN 免构建 | 新的极简项目可考虑；当前 Vite 已工作，保留锁文件和打包资产更利于多设备一致性，不值得为少一个构建步骤迁移 |
| 至少三条迭代记录 | 作为文档质量目标，不凑数、不编造；工程修复不冒充真人体验改进 |
| 从第一分钟记日志 | 后续实时记录；此前未精确计时的阶段如实保留缺口 |

题目三个方向中，本项目归属方向二。自由选择其他题材不等于可以脱离三个方向；影子匹配、透视谜题等必须重新证明归属，不能仅凭 3D 更强就优先。

## 3. 新增定向测量：当前最重要的设计问题

复现命令：`node --experimental-strip-types scripts/triage-probes.ts`。

结果文件：[triage-v01.json](../evidence/triage-v01.json)。这是只读规则实验，不是浏览器重测或真人试玩。本轮未声称重新验证已有 16 项测试或线上状态。

### 3.1 演示时间与信息量不匹配

默认布局首次住宅起火为 3.7 秒，最后一栋起火为 9.6 秒，全部住宅烧毁为 19.6 秒，固定结算为 45 秒。

- 9.6 秒以后已无法挽回任何住宅，玩家也不能在模拟中改建。
- 19.6 秒以后仍需等待 25.4 秒才看到结算。2× 加速能缩短等待，但不会增加决策或信息。
- 45 秒仅为模拟时间；建造、读提示、读结果和修改仍需额外时间，所以尚不能声称完整循环 ≤ 60 秒。

修改方向：保留第一次关键传播的可读速度；结果已确定时提前结算或允许直接看结果。使用严格的结果稳定条件，不能仅因暂时没有新起火就提前停止，因为热量仍可能累积。完整循环目标为约 40–60 秒，需实测。

### 3.2 防火带的改进反馈接近二元跳变

保持默认 12 栋住宅不动，对西侧 B2–B7 六格的全部 64 个防火带子集进行枚举：

| 结果 | 配置数 |
| --- | ---: |
| 保住 0 栋 | 63 |
| 保住 1–11 栋 | 0 |
| 保住 12 栋 | 1 |

唯一满保护配置为完整六格防火带，花费 6 / 12 点。

解释：这个局部策略空间几乎只反馈「没堵完」和「完全堵住」。逐步添加一格时无法从幸存数量看到进步，容易把实验变成寻找唯一封口规律。

边界：这不是所有可能布局的穷举。移动住宅、其他防火带位置、混合消防策略可能产生中间结果，不能据此断言整个游戏只有两种结果。

### 3.3 已有多解，尚未证明有值得比较的策略

默认住宅不动，在剩余 24 个建设格枚举消防站：

- 一座消防站：24 种位置，最多保住 3 栋，没有达标方案。
- 两座消防站：276 种组合，26 种达到 8 栋目标，其中 15 种保住 12 栋，花费 8 点。
- 当前完整防火带花费 6 点即可保住 12 栋，而且没有其他目标要求保持通道畅通。

解释：在这个固定场景内，已经知道完整隔离方案的玩家缺少尝试更贵消防方案的明确动机。不能把「两种方法都能通关」直接当作「两种策略互有优势」。未来需要让目标或地形产生真正的取舍。

边界：只比较上述固定住宅配置，不是全局最优性证明；没有遍历混合设施或移动住宅。

### 3.4 复盘记录还没有充分转化为解释

实现中的 `source` 是点燃当步最强的相邻热源，历史热量可能来自多个方向。事件本身是真的，但它不是完整的历史因果归因。当前结果只列出最早四个住宅点燃事件，也没有直接说明「哪处缺口让火绕行」或「哪个消防范围内能力被分摊」。

修改方向：区分传播记录与原因解释；优先高亮与玩家改动有关的那条路径。若给出归因，需要记录对应证据，避免把单条箭头讲成唯一原因。

## 5. 推荐路线 A：火线街区：三次防灾实验

### 一句话与方向映射

**「用有限防灾预算重建一片街区，试过火势后，换一个布局保住更多住宅。」** 归属方向二，保留建设、实验、观察破坏和连锁变化、调整重建的循环。

变化的重点是收敛决策和提升反馈，不是再堆三张地图。复用同一套场景，先验证一个具有中间结果的实验，再从同一配置结构做三个有不同决策的问题。

### 约束与内容配表草案（尚未实现）

| 实验 | 要学习的判断 | 参数 / 空间约束 | 期望反馈 |
| --- | --- | --- | --- |
| 01 截断与绕行 | 理解局部隔离如何保住部分住宅 | 分成可独立保护的两个小片区；保留住宅搬迁和建造 | 不同调整出现部分保护，而非只有 0 / 12 |
| 02 通道必须保留 | 比较隔离与消防覆盖 | 预设必须畅通的通道格，限制完整封墙，且明确在地图标出 | 消防覆盖承担封墙不能替代的作用 |
| 03 风向变化 | 迁移上一轮学到的原理 | 从已验证配置选择另一风向与起火边 | 上一方案需要调整，但规则不临时改变 |

「通道」只作为禁放防火设施的可见约束，不实现居民或车辆寻路。边界源点和风向参数需要真正接入模型，不只换界面箭头。

配置字段建议：`id`、`learningGoal`、`wind`、`ignitionCells`、`buildableMask`、`corridorMask`、`initialHomes`、`budget`、`targetSaved`、`hintTier`、`referenceLayouts`。生成器按配置装配场景；每个发布配置附可复现参考解。不做无限随机地图。

规则验收：至少两种合法方案存在可解释取舍；预先指定的三个递进修改在该实验中产生可区分的中间保护结果。数值和布局通过模拟后才能定稿，表格本身不证明可解。

### 只处理两个真正的技术问题

1. 把固定地图输入与风向、源点、建设限制抽成可验证的场景配置。
2. 把模拟结果转换为简短、可解释的复盘，并处理可靠结算时机。

渲染、网格交互、固定时间步、仓库、存档结构和 Vite 继续复用。暂不加入高度、真实物理、AI 角色、音画素材制作或新灾害。

### 后续 4 小时预算示例

仅为规划，不是实际工时或承诺：实现 96 分钟（40%），真人试玩和复测 72 分钟（30%），内容配置与节奏 36 分钟（15%），文档 36 分钟（15%）。先保住一条经试玩验证的完整循环，工期不足时缩为两个实验。

## 6. 全新路线 B：双视点巡检

### 一句话与方向归属

**「从两个观察位检查同一值班室，发现违反正常规则的空间异常就报警，否则放行。」** 归属方向一：反复探索同一环境，建立正常认知，识别异常，通过判断推进巡检。

### 为什么值得替换比较

3D 深度与遮挡直接影响信息获取，玩家要主动换观察位才能消除误判。只需一间房，避免完整走廊与自由移动碰撞；两个固定观察位用平滑镜头切换。所有正常不变量始终写在告示牌上，不要求背住不可见的原样。

建议每轮 15–25 秒，六轮加简短入门约 2–3 分钟；时间是验证目标。使用完成六次巡检而非连续六次正确，避免失误使流程无限延长。

### 六条异常内容的低成本结构

先只做三类几何关系，每类两个明显程度，共六条，另有正常状态：

| 类型 | 正常规则 | 异常参数 | 换视点的价值 |
| --- | --- | --- | --- |
| 悬空 | 箱体必须落在支撑台上 | 沿竖直方向抬升，位移分明显 / 轻微 | 前方遮挡可能掩盖底部间隙，侧面能确认 |
| 断接 | 管道必须接入标色接口 | 管端沿深度方向离开接口 | 正面投影可能重合，侧面看到断口 |
| 穿插 | 实体必须位于标定围栏内，不能穿过围栏 | 沿深度移动，制造可见交叠 | 从另一角度确认前后关系 |

每条配置带类型、位移、有效观察位、可见窗口、难度、复盘高亮对象。可见性不能只凭位移数值认定，需要灰盒检查和真人判断。

前两轮只投放明显、可自证异常或带提示的正常样本；后续混入轻微变化与正常样本。错误后短暂高亮证据，代价是压迫感下降，因此本作以空间判断为卖点，不依赖恐怖感。

### 两个技术问题与止损条件

1. 两个观察位及镜头插值，确保目标在不同屏幕比例下确实能被看到。
2. 参数化异常切换与完整复位，保证每轮恢复正常模板，不遗留上一轮状态。

不做真实影子异常、NPC、物理碰撞、自由移动、随机几何生成或图像相似度判定。

先用约 45–60 分钟预算验证一间灰盒房、三个异常和两个视点；这只是预估。安排至少一次他人试玩，观察是否理解正常规则、是否主动换视点、错后能否解释证据。如果两个视点没有改变判断，或三个异常都需要口头解释，就没有证据证明它优于现有路线，不继续补内容。

## 7. 全新路线 C：立体断路塔

方向二。一句话：「在电磁脉冲来袭前布置绝缘模块，切断三层装置里的危险连接，保住核心。」

用离散节点与明确的上下层连接模拟连锁，不用刚体、寻路或敌人 AI。3D 帮助玩家观察上下穿接关系，两个固定视角和楼层高亮避免遮挡把谜题变成找像素。

两个技术问题是立体模块放置的可读性与三维连接传播。关卡配表包含节点、连接、源点、可放位置、预算与核心目标。

它具有较强 3D 展示潜力，但从现有平面模型迁移后，还需重新验证空间理解、模块价值和至少三个好问题。当前证据不足以把它排在前两条路线之上。若去掉视觉高度后选择完全不变，也不能宣称 3D 必要性已经成立。

## 8. 真正应该补充的试玩与记录

这一轮的新数据来源是确定性模拟，不能补写成真人发现。建议让 1–3 名首次玩家分别尝试候选，用相同引导程度和体验预算记录：

- 无口头教学时是否能开始，在哪句规则或哪个按钮停住。
- 完成一次「行动 → 反馈 → 调整 → 再验证」实际用了多久。
- 能否用自己的话解释上次失败和本次修改的目的。
- 是否主动要求再试；如果停止，记录原话和具体位置。

小样本只能帮助发现问题，不用于声称统计意义上的偏好胜出。skill 的外部试玩要求在本轮仍未满足，因为没有他人的实际反馈。

现有记录可按真实证据补充代价与边界，例如：

| 已发生改动 | 已知代价 | 已知边界 |
| --- | --- | --- |
| 西侧连续干草带替代孤立入口 | 增加环境规则说明；修复简单封口后，仍可能产生完整封墙解 | 只验证当前地图，不能证明策略平衡 |
| 固定模拟与保留布局重试 | 同场景可预测，长期变化性有限 | 能比较方案，不能证明玩家愿意重复玩 |
| 加入事件复盘与坐标 | 阅读负担上升，事件来源也不等于完整历史归因 | 有助定位发生了什么，是否解释为什么仍待试玩 |

不要为了满足条目数编造观察者、玩家原话、提升百分比或改动效果。

## 9. 本轮决策

1. 不把当前 v0.1 当作已完成体验验证的最终作品。
2. 优先验证路线 A 是否能修复反馈断层和空等；此推荐基于未来交付成本与可测问题，不是沉没成本。
