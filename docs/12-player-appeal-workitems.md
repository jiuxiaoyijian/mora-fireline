# 让《火线街区》好玩、有吸引力：玩家体验工作项

> 后续更新：用户已确认林缘小镇、木石小屋与温暖微缩风格，并授权实施。本文保留当时提案；当前以 [体验规划](13-experience-plan.md)、[排期表](14-work-schedule.md)、[美术规范](15-art-direction.md) 为准。

日期：2026-09-15。基线：`311bd97`，实际游戏仍为 v0.1。

用户指出：看上去像游戏很重要，开始界面、交互、单局流程和结算反馈应被整体设计；题材与美术会影响玩法的友好度、合理性与建设动机。本文件整理这一维度的工作项，供评估。题材、名称、流程数值和素材方向均为建议，尚未确认或实现。

## 1. 对上一版优先级的修正

开始界面、题材定位、基本美术语言、单局节奏和结算演出进入首个完整版本，与规则修复同步。它们决定玩家怎样理解行动、期待反馈，不能全部拖到多关卡阶段才处理。

首个交付目标调整为：**一个题材自洽、有开始和结束、建造有手感、结果值得关心、愿意再试的完整单关。**

已有规则问题仍需修复：空等、全有全无的防火带结果、设施缺少取舍。表现包装不能代替这些改进，规则正确也不能代替完整的玩家体验。

## 2. 先回答五个题材问题

| 必须回答的问题 | 推荐提案：林缘小镇的火险季 | 对实际工作的影响 |
| --- | --- | --- |
| 我是谁？ | 负责新社区建设的规划者 | 开场一句委托，界面使用家园与建设语言 |
| 为什么要建？ | 为 12 户家庭规划住所，完成社区建设委托 | 住宅数量对应安置目标，不是无来由的开局校验 |
| 为什么会着火？ | 山外雷暴引起山火，干燥植被与风将火带向小镇；属于游戏设定 | 威胁从场景外进入，有风与烟的预告；玩家不是纵火者 |
| 我能做什么？ | 在火势抵达前调整建筑、清理隔离带、布置蓄水喷淋设施 | 建造期可自由修订方案，灾害期检验布局；准备时间不必真的倒计时 |
| 为什么再来？ | 保住更多自己安排的家园，或用更少预算完成保护目标 | 布局保留、同条件前后比较、清楚的下一次优化方向 |

时间线建议明确区分「规划准备」与「火势抵达」。建造期的移动和撤销属于规划修改，不表现成正在起火时瞬移房屋。再试是同一关卡的重新挑战，不需要额外编造循环灾难或时间旅行设定。

进入灾害阶段前可用一句「居民已转移，守住大家的家园」明确本作保护的是社区财产和建设成果。保留投入与损失的情绪，不新增居民 AI、伤亡统计或逃生系统。

### 题材备选与取舍

| 方向 | 适合之处 | 容易产生的预期问题 | 建议 |
| --- | --- | --- | --- |
| 近现代林缘小镇，木石住宅，外部山火 | 草地、木屋、隔离带、蓄水喷淋容易形成一致视觉 | 仍需说明喷淋重在预防，不能把它表现成万能灭火站 | 推荐先评估 |
| 现代城市街区，建筑事故起火 | 当前项目名称和已有界面易沿用 | 高楼、道路、消防站会使人期待消防车、室内救援和主动灭火 | 可以做，但需接受额外表现与规则解释成本 |
| 架空部落村庄，火季侵袭 | 简单造型、自然材料和村落情感容易统一 | 水井与水桶易让人期待搬水劳动；现代喷淋设施风格不匹配 | 需要重设计设施表达，作为备选 |

当前不以人为纵火、查明起火原因或追捕纵火者作为主线；它们会引出调查和对抗预期，超出建造防灾循环。用户可以选择不同题材，以上并非已确定设定。

## 3. 美术与声音需要服务什么

推荐视觉方向：**温暖的桌面微缩小镇，木石建筑、清晰轮廓、少量生活细节，遇到火情时出现明确的氛围变化。** 保持项目名《火线街区》，是否增加题材副标题待定。

最低美术交付不是整套高精模型，而是一页风格规范和一组真正影响读图的对象：

- 场景：林缘、两三个住宅片区、清晰道路或空地、场景外火线，让网格看起来有地理原因。
- 建筑：住宅与喷淋设施轮廓明显不同；住宅可有两三种同功能外观，增强社区感，不增加数值品类。
- 状态：规划预览、建成、受热、起火、废墟、被保护都可识别；颜色之外还有轮廓、图标或动画区别。
- 界面：同一字体层级、按钮形状、图标与选中反馈；标题、游戏 HUD、结算有不同的信息密度。
- 氛围：准备时温暖安静；预警时风与远烟增强；危机时火势与声音上升；结束时安静下来，保住的房屋亮灯。
- 音效：选择、放置、取消、错误、起火、受保护、结算提供少量一致的反馈；支持静音，声音关闭仍可理解。

不依赖大量烟雾遮住关键格子，不用强闪烁表达所有危险，不让特效遮住覆盖与状态。新增外部素材需记录来源；本轮没有生成或采购素材。

## 4. 单局按玩家的情绪和行动组织

完整流程提案：

**标题与场景吸引 → 接到建设任务 → 做出第一笔建设 → 检查防线 → 火势抵达 → 看见方案发挥作用 → 成果揭晓 → 选择改进或下一关。**

| 阶段 | 玩家应该感到什么 | 需要看见 / 做什么 | 必须避免的问题 |
| --- | --- | --- | --- |
| 标题 | 这是一个我愿意进去的小镇 | 活的 3D 场景、标题、一句玩法承诺、开始 / 继续 | 开屏就是密集参数和技术说明 |
| 接任务 | 知道我是谁、要保护什么 | 简短委托、安置数量、可用建设资源、来火方向 | 大段世界观或长教程 |
| 初次建造 | 我亲手把这里变好了 | 一个可完成的小任务，明确预览、放置落地、资源变化 | 强制先看全城烧毁，第一次行动只有失败 |
| 自由准备 | 我的布置有选择 | 搬迁、隔离、喷淋、撤销与风险预览 | 费用、规则或建设限制要靠试错才能知道 |
| 火势抵达 | 我的方案要接受考验了 | 点击「准备好了」；短预警、画面和声音过渡 | 使用「启动火灾」使玩家身份与故事冲突 |
| 危机 | 紧张、能看懂防线有没有用 | 火的路径、被挡住的位置、保护生效和损失；暂停、加速或查看结果 | 高速连锁看不清，或胜负已定还长期等待 |
| 结算 | 有成果，有遗憾，也有下一步 | 先展示地图结果，再给保护数量与目标达成，最后给一条可行动线索 | 只有冷数字、长日志、真假不分的赞美 |
| 再挑战 | 我知道这次想改哪里 | 主按钮「保留布局，再试一次」；成功后再提供下一关 | 重试清空全部建设、跨场景混比结果 |

首次体验包含标题与教学，不强行要求 60 秒内结束。熟悉后的一次重复实验仍以约 40–60 秒为待测目标；情绪与信息节奏优先于机械压缩时长。

## 5. P0 工作包：首个完整单关必须具备

P0 是本轮建议提升后的优先级。下表是待实施工作项，不是已完成清单。

| ID | 玩家目标 | 工作内容 / 具体产物 | 验收方式 | 依赖 |
| --- | --- | --- | --- | --- |
| A01 | 我知道自己为何行动 | 一页题材设定：玩家身份、建设委托、火灾来源、准备到灾害的时间线；统一主按钮与设施名称 | 看过开场的玩家能复述要建什么、保护什么、火从哪里来 | 先选定题材 |
| A02 | 第一眼愿意点开始 | 最小风格规范 + 代表性 3D 场景；标题、开始 / 继续、声音和玩法入口 | 不读 README 能识别建设防灾主题；主要入口清楚，进入后风格与标题一致 | A01 |
| A03 | 一进入就有明确行动 | 简短任务卡 + 一次实际建造引导；提供有希望的初始布局，可跳过已看引导 | 无口头解释能完成首个建设动作；不通过强制失败教规则 | A01、局部保护规则 |
| A04 | 建造本身有手感 | 悬停、落点预览、可放与不可放反馈、费用和覆盖提示；直接搬迁、取消、撤销；轻量落地动画与声音 | 误操作可恢复，资源与落点可信，常用操作不依赖先拆再补；无声也清楚 | A02、现有建造规则 |
| A05 | 感到单局有起承转合 | 标题、准备、预警、危机、结束的状态与镜头脚本；暂停菜单的继续 / 重试 / 返回标题规则 | 一次完整流程无生硬断点；返回标题后的进度处置明确；预警不偷跑或暗扣建造时间 | A01–A04 |
| A06 | 看到选择产生效果 | 保留规则改进：部分保护、设施取舍；做出挡火、绕行、喷淋保护和房屋损失的可读反馈 | 玩家能指出一个有效或失效的布局选择；表现由实际模拟状态驱动 | 上版 P0-2、P0-3 |
| A07 | 对结局有感觉 | 成功 / 未达标但有改善 / 明显失守三种结果表达；先场景后成绩，保护目标与前后差异，关键提示与重试入口 | 成功有明确收束；未达标不冒充通关，失败不过度惩罚；下一次操作清楚 | A05、A06、结果数据 |
| A08 | 还想再做一次 | 保留布局、改动前后比较、达标后的省预算目标；同情景内保持灾害条件一致 | 玩家能说出下一次想尝试的改动；比较不跨规则版本或不同灾害 | A07 |

### 结果表达示例（不是实测结果）

- 达标：「8 栋家园保住了，完成本次保护目标。」地图先亮出保住的片区，再展示数字。
- 未达标但改善：「保住 6 栋，比上次多 2 栋；距离目标还差 2 栋。」提示与本次事件有关的一个缺口，不假装已经胜利。
- 明显失守：「这次防线失守了。火从西侧缺口进入，调整这里再试。」具体归因必须有真实证据，不能使用与布局无关的固定句子。

先突出保护数量，预算作为第二信息。暂不加复杂星级、总分、勋章库或升级奖励；如果没有真实意义，这些元素不会自动带来吸引力。

## 6. P1 工作包：在真实体验后继续增强

| ID | 工作内容 | 增加的玩家价值 | 范围约束 |
| --- | --- | --- | --- |
| B01 | 住宅少量外观变化、路牌、生活小物、结算灯光 | 建成的街区更像自己的家园，保护结果更具体 | 不添加居民寻路与模拟生活系统 |
| B02 | 第二个街区或第二种明确预报条件 | 把已经学会的策略带到新问题中 | 一张图流程成立后再做，规则变化提前告知 |
| B03 | 更完整的环境声与音乐层次 | 建设放松、危机紧张、成功释然 | 先保证静音可玩、音量适宜，不先做大型配乐包 |
| B04 | 更方便的连续建造、快捷键提示和镜头辅助 | 减少重复操作，观察更自在 | 以实际误点、遮挡和重复操作记录决定是否增加 |
| B05 | 关卡完成后的社区总览 | 给短篇游戏一个完整终点和建设成果 | 使用已有场景，不做长期经营和跨局经济 |

基本状态反馈与必要音效已属于 P0；这里指额外的丰富度，不再把所有美术和声音都统一放到后期。

## 7. 与已有计划合并后的实施顺序

1. **题材与体验定稿**：先确定 A01 的五个问题，画出开始、准备、危机、结算四个关键画面与状态关系。用户选择题材后再投入对应素材。
2. **做一段完整单关**：A02–A08 的最小版本与规则修复同步推进。只做一个场景，也必须能从标题玩到结算并重试。
3. **用户与首次玩家体验**：观察理解、操作、情绪和重试动机，修复阻碍；技术 QA 单独记录。
4. **扩展与提交**：依据反馈选择 B 类工作，再完成已有发布与公网验收门槛。

v0.2 的含义因此更新为「有题材与完整体验的单关」，不再仅是规则修复包；v0.3 再决定关卡和表现丰富度。预算不足时砍第二关与装饰，保留清晰开始、基本建造手感、关键事件反馈和完整结算。

## 8. 怎样验证“好玩、有吸引力”

以下是观察目标，不是已经测得的结论，也不预设用户一定喜欢推荐题材。

| 观察时点 | 核心问题 | 记录什么 |
| --- | --- | --- |
| 进入前 / 标题页 | 能看出是什么游戏，愿不愿意点开始？ | 玩家对题材与玩法的描述，以及选择理由 |
| 第一笔建设后 | 有没有觉得自己在建设一个地方？ | 能否描述建设目标；对反馈的自发评价 |
| 危机中 | 关不关心哪些房子会保住，能否看懂效果？ | 关注位置、惊讶点、看不清或误解的事件 |
| 结算后 | 成绩是否符合看到的过程？ | 是否理解目标达成与损失原因，是否感到突兀 |
| 再次开始前 | 还想不想试，打算改什么？ | 自发提出的计划；停止体验时的原话 |

至少安排一次他人体验；可用 1–3 人发现主要问题，但不把小样本包装成偏好统计。不要先告诉玩家正确答案。分别记录主观偏好、可复现操作问题、规则问题和视听辨识问题。

## 9. 当前待评估决定

- 推荐采用近现代林缘小镇与自然外部山火；现代城市和架空村落保留为备选，尚未选择。
- 推荐建设动机是安置住户、保护建设成果，避免只有“完成实验指标”。
- 推荐微缩模型式温暖美术，灾害阶段有紧张变化；不是全程轻松，也不以惨烈灾难为卖点。
- 开始界面、操作反馈、完整单局与结算提升为 P0，这是对上一版计划的优先级修正。

本轮只整理文档。未修改当前游戏、生成资产、进行新试玩或公开发布。
