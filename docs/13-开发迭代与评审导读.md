# 开发迭代与评审导读

本项目由用户提出体验目标与反馈，Codex 完成实现和技术验证。以下是可核验的设计决策摘要，不是私人思考逐字稿；未记录精确工时，也没有真人试玩数据。

建议评审先在线体验第一、四、七关，再看下表。现行规则见 [规则](07-当前游戏规则.md)，未实现项见 [接续指南](09-开发接续指南.md)，逐次检查见 [开发记录](04-开发与试玩记录.md)。

| 引入功能 | 遇到的问题 / 依据 | 选择的解决方案与取舍 | 执行和验证 |
| --- | --- | --- | --- |
| 建造—模拟—复盘循环 | 需证明布局而非随机运气影响结果 | 固定步长、种子和预算；规则与渲染分离 | 规则测试检验重试一致性、跳播与完整演练一致；形成最小闭环 |
| 网格规划 | 用户反馈方格逻辑感强、代入感弱 | 六边形邻接，加低多边形山海远景、透视镜头；远景不参与规则 | 邻接互逆/距离测试，海岸场景与镜头浏览器 QA；见 880c66e |
| 河流与海浪 | 用户认为水景融合不自然 | 统一河海网格与岸线，程序噪声碎浪；避免昂贵反射 | 固定几何体 600 帧回归；见 3827420 和性能文档 |
| 深色 UI | 用户明确反馈加深后不好看 | 参考木框纸面、分层 HUD；首页用巡护手记建立身份 | 桌面与横竖屏浏览器验收；见 67d84a1、UI 文档；真机待测 |
| 拖动建造 | 手势采样可能漏格或误触 | 沿实际指针路径采样，每笔同格只处理一次，区分镜头与绘制 | 8 项输入回归；见 9657e84 |
| 八关与固定房屋 | 用户要求明确目标、教学递进，房屋不可移动 | 防灾规划员身份；由隔离教学到风向、材质与飞火组合 | 八关无防护失败、全保与三星解自动验证；浏览器走通解锁；见 b8cdea2 |
| 喷淋与飞火 | 用户反馈覆盖过大、后期轻易破解 | 半径一圈、共享两次储备、四秒补充；草地火头可产生不同落点飞火 | 重校地图与预算；第七关双喷淋 5/8，加隔离 8/8；规则测试覆盖耗尽、补充和重叠 |
| 更多场景与持续动画 | 用户反馈一直卡顿、镜头也不顺 | 修复镜头反复重置画布；静态合批、同格预览复用、重试复原模型 | 同布局调用 296→84、CPU P95 5.1→2.5ms；浏览器仍约32 FPS，未证明真机问题完全解决。前后服务器模式不同，比较有边界 |
| 湿润与飞火提示 | 用户说建筑下蓝圈不明显 | 状态移到屋顶；蓝水滴可拦截、金色缺压；飞火始终橙色，落地按实际结果区分溅射 | 固定128实例与4096顶点容量，额外一个绘制对象；回归验证重复演练不增几何体；浏览器视觉检查 |
| 第八关结算 | 用户反馈终章仍只有复盘，没有完结感 | 完结标题、累计星级、复制分享、确认重开；保留关卡回访 | 区分终章与全通；分享失败可手动复制，重开前保存可恢复备份；浏览器检查结算、分享和取消 |

## 如何理解验证结果

- 自动检查证明规则、数据和部分性能结构符合约定，不能证明游戏有趣。
- AI 浏览器 QA 检查操作可达、文案、布局和错误；桌面模拟尺寸不是真实手机测试。
- CPU 基准不等于 GPU 帧率；性能样本详见 [性能回归](10-性能回归.md) 及原始 JSON。
- 下一步优先招募首次玩家，记录能否独立理解喷淋储备、主动修订防线，以及后期是否出现多种有效方案，再决定扩展机制。
