# 玩法循环与体验优化规划

状态：设计评估，以下新增方向均未实现，不代表本轮上线内容。基于当前八关代码、用户反馈与已有自动/浏览器验证；尚无真人试玩结论。

## 建议先解决什么

优先强化“看懂威胁 → 做出选择 → 看见效果 → 据此改进”的循环。先解决持续卡顿和失败原因不够明确，再增加关卡解法差异与通关后的自选挑战。暂不扩展长期成长和大量新设施，避免用内容量掩盖单局决策不足。

现有循环是：接受委托 → 布置固定住宅周围的设施 → 20–45秒演练 → 看保护数/星级/起火事件 → 保留布局重试或进入下一关。八关具备可行解，但“可解”不等于“有多种值得探索的解法”。

| 环节 | 当前依据 | 可细化方向 |
| --- | --- | --- |
| 建立目标 | 有规划员身份、关卡目标与委托；前几关提示直接给坐标 | 把目标、观察线索、完整解法分成逐层自选提示，让玩家先形成判断 |
| 做出选择 | 隔离挡地面、喷淋降温和有限拦截；7/8关仍复用相近屋群 | 让入口数量、木砖比例、风向和预算分别改变设施价值，避免仅叠加飞火数量 |
| 观察验证 | 有屋顶状态、落点预警和储备；用户持续反馈卡顿 | 先取得真机帧数据；关键事件可定位、可暂停读懂，不增加常驻说明条 |
| 失败再试 | 已列最早四次起火，可定位；同会话只比较保护总数 | 关联火源、落点与储备，保留两套布局作同条件对照 |
| 成功后继续 | 已有三星、终章分享与重开 | 解锁可选挑战契约与关卡变体，让重玩改变规划目标而非重复同一答案 |

## 成本与优先级

成本为一名熟悉现有工程的开发者完成最小版本、规则回归、浏览器检查和文档的粗估人日（每人日约6–8有效小时），不是已发生工时或交付承诺。不含招募等待、原创美术和真实设备采购；规则重平衡可能显著增加成本。P0为下一轮优先，P1在基础体验通过后实施，P2需先验证需求。各项有重叠，不能直接相加当排期。

| 优先级 / 方向 | 最小方案与预期收益 | 估算成本 / 触及范围 | 风险、依赖与验收 |
| --- | --- | --- | --- |
| P0 性能与镜头稳定 | 桌面和目标手机固定场景采样；按证据优化GPU或输入瓶颈，必要时自适应画质 | 2–4人日，中；view、render-size、performance、输入 | 依赖真实设备；同视口/画质/关卡比较帧间隔P95和长帧，记录画质损失；30FPS档争取P95≤40ms，60FPS档≤20ms，均为目标而非现状 |
| P0 失败原因可解释 | 点击首个受损住宅，显示事件时刻、热量变化、飞火来源、储备是否耗尽；一键定位对应设施 | 2–3人日，中；sim事件、main复盘、UI | 目前最大热输入源不是完整因果；新增有限快照，不能将累计热量误归因给单一事件。构造地面/飞火/缺压三类案例，数据对齐规则；试玩能说出下一步修改 |
| P0 渐进提示 | 第一层说明目标，第二层高亮危险区域，第三层才给坐标；失败后主动提供入口，不强制弹窗 | 1–2人日，低；levels、模板、提示状态 | 防止教学变猜谜；保留可访问的完整帮助。观察新玩家能否在不读坐标答案时完成前两关，记录卡点和提示使用层级 |
| P1 喷淋布置预览 | 建造悬停显示覆盖户数、共享储备与重叠设施；点选单座可聚焦服务对象 | 1–2人日，低至中；view、main | 不承诺“放这里必胜”，不预运行整局求最优解；边界与重叠覆盖必须和sim一致，同格悬停不新增几何体 |
| P1 方案A/B对照 | 保存两套本关布局，切换并用同种子跑完整模拟；对比预算、保护户数、首个损失与缺压次数 | 2–4人日，中；存档、main、复盘 | 只比较相同规则版本；迁移不能覆盖旧进度。验证切换不混用布局/成绩，玩家能指出具体哪处改动产生收益 |
| P1 关卡差异化 | 先重做第5/7关各一个变体：5关侧重木砖资源分配，7关用不同入口/距离改变隔离与喷淋价值 | 2–4人日，中；levels、关卡测试 | 不同时新增设施和改全部地图；先保留原关用于对照。每图验证无防护失败、目标/三星可达，并人工检查至少两类不同设施配比的有效方案，不把对称换位算新解 |
| P1 演练节奏与反馈 | 首次关键事件提供可选暂停观察；火星位置作帧间插值，拦截/突破用短音色和局部脉冲区分 | 2–3人日，中；播放、feedback、audio | 默认不频繁打断，尊重静音/减少动态；暂停、2倍速和跳播不改变结果；固定对象池，性能预算不退化 |
| P2 可选挑战契约 | 通关后开放“限一座喷淋”“保护指定木屋”等两个手工挑战，不影响主线解锁 | 2–4人日，中；场景约束、计分、存档 | 先证明关卡有多解；预算/限额必须前后一致，挑战与原成绩分开，逐个验证可达；避免只有增加难度没有新选择 |
| P2 有限应急操作 | 独立实验关一次主动补水，在已预告的阵风前使用；对比纯规划版本 | 4–7人日，高；输入记录、sim、回放、教学 | 可能变成拼反应并削弱规划；操作按模拟tick记录，暂停不免费重复使用，重试可重放。若玩家关注操作时机超过布局，则不并入主线 |
| P2 身份与完成感 | 关卡结束点亮地图对应街区，用一两句居民回信对应实际保护结果；可导出分享卡 | 1–3人日，低至中；UI、文案、图片导出 | 不新增数值成长；失去房屋时不写全保文案，不阻挡重试；分享图片失败仍可复制链接 |
| 暂缓 扩设施/长线成长/程序随机关 | 等八关多解与重玩意愿有实测依据后再立项 | 7–15+人日，高且不确定 | 联动平衡、生成可解性与存档成本大；永久强化会破坏同条件方案比较；当前不推荐 |

## 推荐落地顺序

1. **先建立可读、可操作的闭环。** 做性能定位、渐进提示和最小失败诊断，预计4–8人日（共享UI工作后粗估）。用第1/4/7关测试，不增加新机制。
2. **再提高每次修改的价值。** 方案A/B、覆盖预览与两个关卡变体，预计5–9人日。优先验证“改一处为什么变好”，再追求更难。
3. **最后验证重玩动力。** 在前两轮改善成立后，从挑战契约或应急操作中选一个实验；不同时加入，便于判断收益。身份回信可作为低成本补充。

第一轮若设备性能仍不达标，应缩减表现开销而不是继续追加特效。若玩家失败后能理解原因却不想重试，优先调整关卡决策和目标，不继续增加说明文字。

## 验证方法与停止条件

建议邀请5–8名首次玩家做形成性观察，小样本用于发现问题，不用于证明统计显著。先不提供答案，依次体验1/4/7关；同一人学习后不能再作为“首次体验”基线。记录设备、提示层级、首次有效布局、失败解释、修改位置、主动重试及通关后是否自选挑战。只记录必要数据；目前未接入线上行为采集。

验收目标可暂定：至少4/5玩家能说清目标与设施差异，并在首次失败后提出与证据一致的修改；这只是下一轮验收约定，不是现有成绩。每次记录人数与原始观察，失败样本不能省略。

技术护栏：同种子+布局+输入记录得到同结果；固定住宅不可移动；所有主线关仍有预算内可行解；旧存档有迁移或独立版本；复盘数值对应事件；性能保持同场景可比。若某功能只增加点击或解释量、未产生新判断，先撤回实验，再讨论扩展。
