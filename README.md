# 火线街区 · Fireline

面向 Mora 游戏策划 Vibe Coding 笔试的浏览器 3D 原型。选择方向二「建造与灾害模拟」：布置街区、启动火灾、观察传播、调整布局，并比较同一场灾害下的结果。

> 当前阶段：v0.2.0-dev.3，六边形山谷、两片住宅区、连续地形和可调透视镜头已实现。保持 1920×1080 游戏画幅。完整 v0.2 仍需设施平衡与真人试玩，已授权公开发布 Pages，包含海岸、雪山融水河与性能回归。详见 [六边形与场景迭代](docs/20-六边形山谷与镜头迭代.md)。

本地接续已补充全毁自动收束：住宅全部烧毁后跳过剩余演出，仍计算完整 45 秒模拟与事件。当前六边形默认布局在 19.2 秒触发，减少 25.8 秒无效播放。工程分层、风险与后续顺序见 [工程结构与接续分析](docs/19-工程结构与接续分析.md)。

用户已确认近现代林缘小镇、木石小屋、温暖微缩模型风格。当前加入实时场景标题、直接搬迁与撤销、预警与暂停、可跳过演出的完整结算、家园成果与基础合成提示音。

游戏采用 16:9 等比适配，非同宽高比窗口留边；三维场景内叠加资源、建造工具与控制栏。主菜单、暂停、帮助、确认和复盘均在游戏画面内。详见 [固定画幅与交互设计](docs/18-固定画幅与游戏内交互设计.md)。

## 游戏定位

- 目标体验：为家园建设防线，观察火势，通过修改布局保住更多住宅并理解原因。
- 形式：低多边形 3D 沙盘，斜俯视镜头，鼠标建造。
- 单次模拟：45 秒，可 2× 加速；完整体验目标约 3–5 分钟，仍需真人试玩验证。
- 技术：TypeScript、Three.js、Vite；纯浏览器运行，已按 GitHub Pages 子路径验证静态构建。
- 核心循环：建设 → 实验 → 观察 → 调整 → 再次实验。

## 怎么玩

1. 从标题进入小镇，先铺防火带或布置喷淋，不要求先经历失败。
2. 点击「开始演练」，经过 2.4 秒预警后观察山火；可暂停、2× 加速或直接查看最终结果。
3. 用 12 点预算布置防火带（1 点 / 格）或蓄水喷淋（4 点 / 座）；始终需要安置 12 栋住宅。
4. 结算查看家园成果与首起火线索，保留布局调整后重试；保住至少 8 栋即达标。

默认隐藏格线与坐标，可开启「规划格线」。滚轮缩放，右键拖动环视和调整俯仰，也可用画面内镜头按钮与复位。底部选择工具，再点击地图建造；防火带可拖动连续铺设，逐格撤销；住宅工具选中房屋后点击空地直接搬迁，Esc 或右键取消；撤销或 Ctrl/Cmd+Z 恢复上一步。1–4 切换工具；空格开始 / 暂停。右上菜单可返回主菜单，键盘网格由画面内按钮打开。新规划、恢复默认和清空会先确认。蓄水喷淋负责邻近降温，无法救回已燃烧的住宅。空地仍有可燃植被，不能代替防火带。

六边形布局独立保存在当前浏览器；旧方格存档保留但不自动套用，Git 同步的是代码与文档。重试保留布局，结果对比与最多 40 步撤销仅保留在本次页面会话中。声音默认关闭，可主动开启；刷新不保留运行进度。

## 已知限制与下一步

- 当前仅一个固定六边形火灾场景，局部保护已成立，但完整防线的低成本解仍容易发现。
- 26 项规则、六边形与播放检查不能证明趣味性或数值平衡；需要真实首次玩家的观察和复测。
- 采用固定画幅等比适配，桌面横屏为主要操作目标；竖屏完整留边展示但按钮会缩小，尚未在真实手机或低端设备验收。
- Vite 对 Three.js 分包发出超过 500 kB 的体积提示；其 gzip 大约 135 kB。构建成功，后续以实际首屏与设备性能决定优化。
- 仓库已公开；线上版本通过 GitHub Actions 发布。

## 性能与身份迭代（2026-09-17）

玩家作为松风镇防灾规划员，接受保住至少 8 户、争取 12 户的委托；通过“开始演练”验证并完善方案。深蓝与金色规划界面、常驻委托卡已实现。菜单可切换流畅画质。

运行 `npm run check` 执行规则、性能结构/CPU 基准、类型与构建回归；`npm run test:perf` 单独测性能。30 项检查通过。规划绘制调用 810→345，CPU P95 8.8→5.5ms；当前内置浏览器 FPS 仍约 32，实际设备流畅度待复测。详见 [性能证据与复测流程](docs/21-性能回归与玩家身份迭代.md)。
